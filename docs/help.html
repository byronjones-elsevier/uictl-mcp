UICTL(1)

uictl — find, inspect, and drive running macOS GUI applications

Synopsis

uictl subcommand [options]
uictl [-h | -H | --help | --HELP | -?]

Description

uictl locates running applications, lists and activates their windows, enumerates connected displays, screenshots windows or displays (optionally with a numbered accessibility-element overlay), walks their accessibility tree, clicks, types, sends key combinations, waits for elements to appear, runs OCR, samples pixel colors, and reads/writes the clipboard.

A small background daemon (auto-started on first use, listening on a Unix domain socket at ~/.uictl/uictl.sock) holds Accessibility / Screen Recording permission grants and the element-id cache across invocations. It can also show two small on-screen windows of its own: a brief toast per command, and a live activity-log window (log show) with the option to export that log as JSON.

Every subcommand prints exactly one JSON object to standard output and exits 0 on success, non-zero on failure. This output is intended to be consumed by scripts or AI agents as readily as by a human. uictl can also run as an MCP server over stdio; see the mcp subcommand below.

Subcommands

daemon [start|stop|status]
Manage the background daemon. start is invoked automatically by any other command if the daemon isn't already running.
permissions [--request]
Check, or trigger the OS prompts for, Accessibility and Screen Recording permission.
apps [--all]
List running applications.
displays
List connected displays: id, global-coordinate bounds (can be negative for a display left of/above the primary one), main-display flag, and points-to-pixels scale. index matches what screenshot --screen expects.
windows [--app <selector>]
List on-screen windows, optionally filtered to one application. A name substring matches, and aggregates windows from, every running instance whose name contains it (e.g. both the old and new process right after an app restarts). Each window includes a displayId matching one from displays.
activate --app <selector> [--window <id>]
Bring an application, and optionally a specific window, to the front.
screenshot (--window <id> | --app <selector> | --screen <n>) [--out <path>] [--annotate] [--role <AXRole>]
Capture a window or display to a PNG file. With --annotate, overlays a numbered box on every accessibility element and returns a JSON legend mapping numbers to element ids, roles, titles, and frames.
elements (--window <id> | --app <selector>) [--role <r>] [--title <substr>] [--max-depth <n>] [--max-elements <n>]
Walk a window's accessibility tree; returns each matching element's id, role, title, value, and on-screen frame.
click (--at <x,y> | --element <id>) [--window <id>] [--app <selector>] [--button left|right|center] [--double] [--count <n>] [--hover-cursor]
Click at a screen point or on the center of a specific element. If --window or --app is given alongside --at, the point is relative to that window's current top-left corner instead of an absolute screen point (rejected together with --element, which uses the element's own position). Restores the cursor to its pre-click position afterward unless --hover-cursor is set. When clicking --element, the JSON response includes a verification field (changed/unchanged/unavailable) reporting whether the element's AX state could be diffed before and after — a successful exit status does not by itself mean the click had an effect.
move --at <x,y> [--window <id>] [--app <selector>]
Move the mouse cursor without clicking. --window/--app make --at window-relative, as with click.
scroll --at <x,y> [--window <id>] [--app <selector>] [--dx <n>] [--dy <n>]
Scroll at a screen point. --window/--app make --at window-relative, as with click.
type <text> [--element <id>]
Type text into the focused control, or into a specific element (tries setting its value directly first, falls back to focus + synthesized keystrokes).
key <combo>
Send a keyboard shortcut, e.g. cmd+shift+4 or ctrl+alt+delete.
wait-for (--window <id> | --app <selector>) [--role <r>] [--title <substr>] [--timeout <seconds>]
Block until a matching element appears, or the timeout elapses.
ocr (--image <path> | --window <id> | --app <selector>) [--region <x,y,w,h>]
Recognize text in an image file or a captured window, optionally restricted to a region.
pixel --at <x,y> [--window <id>] [--app <selector>]
Sample the color of a single screen pixel. --window/--app make --at window-relative, as with click.
clipboard (get | set <text>)
Read or write the system clipboard.
log show
Open the on-screen activity log window: a live table of every CLI/MCP call this daemon has handled, with a button to export it as JSON. The daemon has no Dock icon or Cmd-Tab entry (it runs as a background/accessory app), so re-run this to bring the window back if it gets buried behind others.
log export [--out <path>]
Export the activity log as JSON (defaults under ~/.uictl/exports/). Params/response values are the same summarized/truncated/redacted form shown in log show's table, not necessarily the exact raw payload for calls whose output was longer than the truncation limit.
feedback create --category <issue|error|recommendation> --title <t> --body <b>
Draft a new local feedback entry about uictl itself. Stored locally (~/.uictl/feedback.json); nothing is sent anywhere until feedback submit.
feedback list
List all local feedback entries (drafts and previously submitted).
feedback get <id>
Show one local feedback entry in full.
feedback update <id> [--category <c>] [--title <t>] [--body <b>]
Edit a local feedback entry.
feedback delete <id>
Delete a local feedback entry.
feedback check-duplicates <id> [--repo <owner/repo>] [--token <t>]
Check this entry's title against existing GitHub issues (open and closed) without submitting anything. Needs a token if the repo is private — pass --token, set $GITHUB_TOKEN, or have gh already authenticated; otherwise reports that it couldn't check rather than blocking. feedback submit runs this same check automatically.
feedback submit <id> [--repo <owner/repo>] [--token <t>]
First runs check-duplicates; if a likely duplicate is found, the local entry is deleted and nothing is opened. Otherwise opens GitHub's new-issue page with this entry's title/body pre-filled (defaults to uictl's own repo) — it does not create the issue; a human still has to review and click "Create" there. Running this command from a terminal is treated as your confirmation. The uictl_feedback_submit MCP tool instead uses MCP elicitation to ask you to review (and optionally edit) the entry first, since an agent may call it without you having typed anything yourself.
mcp
Run as an MCP server over stdio, exposing every capability above as an MCP tool.

Options

-h, -H, --help, --HELP, -?Show help. All five spellings are accepted at the top level and are normalized onto ArgumentParser's native --help.

Examples

List an application's windows, then screenshot it with element numbers:

uictl activate --app Safari
uictl screenshot --app Safari --annotate --out /tmp/safari.png

Click the element numbered 7 in that legend's id field, then confirm:

uictl click --element 12345-7
uictl elements --app Safari --title "Expected Label"

Files

~/.uictl/uictl.sock
Daemon IPC socket.
~/.uictl/uictl.pid
Daemon process id.
~/.uictl/daemon.log
Daemon stdout/stderr.
~/.uictl/screenshots/
Default output location for screenshot when --out is omitted.
~/.uictl/exports/
Default output location for log export when --out is omitted.
~/.uictl/feedback.json
Local storage for feedback entries (drafts and previously submitted).

Security

ocr, elements, and screenshot read whatever is genuinely on screen, which can include passwords, tokens, or other sensitive text an automated app happens to display; that content is not redacted (unlike type/clipboard set/clipboard get text, which is). It can end up in the activity log (log show, log export) and in screenshot files on disk. Manage and dispose of the activity log window, its exports, and saved screenshots with the same care as any other capture of your screen's contents.

Exit status

0 on success (the JSON response's ok field is true); non-zero otherwise.
